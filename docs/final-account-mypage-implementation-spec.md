# 로그인·마이페이지·보안 최종 구현 명세

## 1. 문서 기준

- 대상 브랜치: `fix/mypage-existing-api-connections`
- PR 대상: `merge`
- 범위: 로그인, 계정, 마이페이지, 신고, 관리자 제재, 상태 동기화
- 이 문서는 현재 배포 가능한 구현을 설명한다. 장기 성능 개선은 `mypage-long-term-optimization-report.md`에서 별도로 관리한다.

## 2. 인증 및 계정

1. 회원가입은 이메일 정규화·중복 검사, 이름 정규화, 비밀번호 정책 검사를 수행하고 BCrypt 해시만 저장한다.
2. 로그인 성공 시 사용자 ID, 역할, 토큰 버전을 포함한 JWT를 발급한다.
3. 보호 API는 JWT뿐 아니라 DB의 계정 상태와 토큰 버전을 재검증한다.
4. 이름 변경과 비밀번호 변경을 지원한다. 비밀번호 변경은 현재 비밀번호를 확인하고 토큰 버전을 증가시켜 기존 JWT를 폐기한다.
5. 회원 탈퇴는 현재 비밀번호가 일치하고 활성 거래가 없을 때만 가능하다. 탈퇴 시 계정 상태와 토큰 버전을 변경한다.
6. 판매자 신청·승인 상태를 마이페이지 프로필과 권한 판단에 사용한다.

## 3. 마이페이지

1. 로그인 사용자 ID를 기준으로 등록 주문·상품, 받은/보낸 제안, 구매/판매 거래, 참여 채팅을 조회한다.
2. 거래는 제안, 진행, 완료, 종료 상태로 단순화해 표시하되 원본 상태 코드는 유지한다.
3. 구매·판매·제안·채팅 목록 API는 선택적으로 `page`, `size`, `status`를 받는다. 파라미터가 없는 기존 호출은 배열 응답을 유지한다.
4. 마이페이지는 최대 100건의 페이지 응답을 받아 6건 단위로 펼쳐 표시한다.
5. 화면 포커스 또는 탭 복귀 시 마지막 조회로부터 15초가 지났으면 다시 조회한다. 화면을 계속 열어 둔 경우 60초마다 상태를 갱신한다.
6. 한 도메인 API가 실패하더라도 성공한 목록은 표시하고 실패한 출처만 재시도할 수 있다.

## 4. 신고

1. 상품·거래·채팅 문맥에서 신고 화면으로 이동할 수 있으며 일반 관리자 문의도 작성할 수 있다.
2. 서버가 신고 대상과 신고자의 소유·참여 관계를 검증하고 피신고자 ID를 결정한다.
3. 신고 시 본문, 대상 스냅샷, 선택 이미지 최대 3개를 하나의 트랜잭션 흐름으로 저장한다.
4. 같은 대상의 미처리 중복 신고와 시간당 10건 초과 제출을 차단한다.
5. 신고 본문, 스냅샷, 증거 파일은 관리자에게만 공개한다. 신고자 응답에는 처리 상태, 관리자 결과, 처리 시각만 포함한다.
6. 관리자는 대기·검토·완료·반려 상태를 관리하며 모든 변경 이력을 기록한다.

## 5. 정지 및 해명

1. 신고 처리 완료 후 관리자는 1·3·7·15·30일 기간 제재를 부과할 수 있다.
2. 기간 제재는 만료 검사 작업으로 자동 해제한다. 다른 유효 제재나 수동 정지가 있으면 계정을 활성화하지 않는다.
3. 수동 정지는 1~500자의 사유를 필수 저장하며 관리자가 직접 해제할 때까지 유지한다.
4. 정지 계정은 정상 JWT를 받지 않는다. 자격 증명 확인 후 `423 Locked`와 사유·종료 시각을 받아 `/suspended`로 이동한다.
5. 정지 화면은 사유, 남은 기한 또는 무기한 상태를 표시한다. 해명 제출 시 비밀번호를 다시 검증한 후 기존 관리자 신고함에 문의로 저장한다.

## 6. 보안 경계

1. `/api/v1/admin/**`는 관리자 역할만 접근한다.
2. 일반 `/api/**`는 인증된 활성 사용자만 접근한다.
3. 정지 해명 API는 JWT 대신 이메일·비밀번호를 재검증하며 응답과 로그인 응답에 `no-store`를 적용한다.
4. 신고 첨부 파일은 서버 저장소에 임의 파일명으로 저장하며 MIME, 확장자, 크기, 개수를 검증한다.
5. 사용자 입력으로 신고자 ID나 피신고자 ID를 신뢰하지 않고 JWT와 대상 도메인 데이터로 계산한다.

## 7. 데이터 및 호환성

1. `users.manual_suspension_reason`에 수동 정지 사유를 저장한다.
2. 신고, 신고 이력, 첨부 파일, 제재는 별도 테이블로 보존한다.
3. 채팅방·제안·견적 엔티티에는 사용자/판매자, 상태, 생성 시각 복합 인덱스를 선언한다.
4. 기존 로그인 모듈과 목록 소비 화면을 회귀시키지 않도록 기존 무파라미터 API 응답 계약을 유지한다.

## 8. 검증 기준

- 계정 정지·기간 제재·수동 정지 충돌 테스트 통과
- 비밀번호 변경·정지 조회·해명 제출 테스트 통과
- 마이페이지 어댑터 및 브라우저 UI 테스트 통과
- `git diff --check` 통과
